Written by package `rn-sw-parity-a` of the integration sweep, from `plans/rn-rewrite/parity-inventory.md` area A (208 rows, A.1 to A.13), by
reading: the check files of `web/dev/checks-app/` (the assertion is read in the file, not taken from the ID), the unit tests, the package
notes (`s1-sidebar`, `s2-drag`, `s3-servers`, `s12-addserver`, `u3-shell`, `p1-sheets-keyboard`, `n3-keys`, `d-e2e`, `v1-pinned-stream`,
`v2-android`), the code of `app/src/screens/{sidebar,shell,servers}` and `desktop/`. Nothing was run. First read at `rn-sweep` `b13110e`; after
the merge of `be37fe4` (the flags of the SEC, AAC, A1 and IM3.5 checks written back, the ports of `A6.4` and `P0.4`, `P7.5` and `A6.3` with the
picker) every row was read again against the checks as they are now. The form is that of `README.md` of this folder.

## How to read the tables

- **Viewports**: `@d,t,p` = desktop, tablet, phone, as the check's own `viewports` line runs it (`@d,t` or `@d` where the check does not run at
  the others, or runs the part that proves the row at those only: the parenthesis says what each proves).
- **`e2e/<name>[APP] step "…"`**: the free script run on the new build (`APP=1 DIST=app/dist-web node web/e2e/<name>.e2e.mjs`, `d-e2e.md`);
  `remotechat` also with `VIEWPORT=phone`. **`desktop/e2e[web build]`**: `AIWB_PAGE=../app/dist-web/index.html npm run e2e` in `desktop/`.
  **`maestro/<flow>.yaml`**, **`app/e2e/xcuitest/keys`**: the device flows (iOS simulator, Android emulator; `v1-pinned-stream.md`,
  `n3-keys.md`, `v2-android.md`). **`hand`**: goal 7.5.
- **Unit tests** are cited as `<package>/test/<file> "name"`. `app/test`, `packages/core/test`, `packages/conn/test` and `desktop/test` run on
  the code of the new build. `web/test/<file>` is cited only for tests that import `packages/core` (its logic and its store, which the new
  build shares); they live in `web/test` today and must move to `packages/core/test` before the old page is retired (R1). Tests of `web/test`
  that render the old page's own components (`sidebar`, `sectioncalls`, `sectionviews`, `serversdialog`, `librarypopups`, `actions`,
  `keptpage`, `saves`) prove the old page only and are **not** cited as proof; where one was the only proof of a row, the row says so.
- **On the new build**: `yes`, `yes, unshown`, `partly`, `no`, `n/a`, as the README defines them, and **`pending`**, a fifth value, as in `b.md`: the
  brief's value for a row that depends on a flag of a check that is still off (a clause of the row is that flag's part); the note names the
  check and the flag, and what is shown meanwhile. Where a row is `yes` and one part of it is not asserted by anything, the note says which part
  ("by code, unasserted", "Unshown: …"); those rows are listed at the end.
- A deliberate difference is named by its `AD-…` (`plans/rn-rewrite/architecture.md`) or the goal's section (`react-native-rewrite-goal.md`).
  "This computer" (its section, its owner's things) exists where the app has a server: the desktop window and the test host; the web build at a
  phone width keeps it, the native phone and tablet app has none (goal 4.1, `platform/thiscomputer.ts`).
