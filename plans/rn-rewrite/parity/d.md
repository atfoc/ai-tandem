Written by package `rn-sw-parity-d` of the integration sweep, by reading (no check, test or script was run; nothing paid). Rows that were
`yes, unshown` or `partly` were then shown by package `rn-sw-gaps-d` (the proofs are in the rows; the new check is `L24-boardui.mjs`, the new

sub-headings, in the form of `plans/rn-rewrite/parity/README.md`. Read with it: `react-native-rewrite-goal.md` 4.1 to 4.6

## How to read the tables

- **On the new build**: `yes`, `yes, unshown`, `partly`, `no`, `n/a` as in the README, and `pending` for a row whose proof on the
  new build is the part of a check that a flag at its top still gates (none is left in this area after the merge of `rn-sweep` at `5774e13`). `yes` means shown by something that exists now; a unit test of the rule counts when the rule is the
  row, and a one-line glue that no test reads is said in the note.
- **Shown by**, abbreviations: `d,t,p` desktop, tablet, phone viewports of a check's own `viewports` line. A check with
  two files for one ID is named by its file (`SEC.7` is `SEC.7-board.mjs` for the board and `SEC.7-drop.mjs` for the chat;
  `AAC.2` is `AAC.2-board.mjs` and `AAC.2-localdown.mjs`). `core/board` is `packages/core/test/board/`, `conn` is
  `packages/conn/test/`, `desktop` is `desktop/test/`, `app` is `app/test/`, `harness` is
  `packages/board-view/dev/harness.mjs` (a free script: the real Excalidraw in Chromium, driven by the bridge's messages;
  it needs Playwright, `README` of `packages/board-view`), `e2e/<name>[APP]` is `APP=1 DIST=app/dist-web node web/e2e/<name>.e2e.mjs`
  (desktop viewport; `remotechat` also `VIEWPORT=phone`), `desktop/e2e[web build]` is `AIWB_PAGE=../app/dist-web/index.html npm run e2e`.
- **`†`** after a test path: the test lives in `web/test/` (the old page's folder) but runs code of `@aiwb/core` that the app
  uses unchanged (`logic/roles.ts`, `logic/boardsave.ts`, `logic/status.ts`, `logic/canvastheme.ts`, `state/conn.ts`,
  `transport/*`, `logic/chatimage.ts`). Those tests prove the app's rule too, **but R1 deletes `web/test` leftovers
  (architecture §11): each marked test must move to `packages/core/test/` first** (some also read `web/src` text; where a cited test does, the row says
  so). See "Findings" at the end.
- Test names are quoted exactly, or from their start up to `…`.
- **Why not / note** for `no` / `n/a`: *device-only*, *deliberate*, *out of scope*, *lost* (the sweep must fix it, listed at the end), *pending*.

## What each area of the new build runs on (so that a row's "where" is clear)

- The board: `packages/board-view` (Excalidraw + `apply.ts` + export, behind the typed messages of `packages/board-bridge`), in
  the page itself on the web build (`window.aiwbBoardView.mount`, AD-40) and in a web view on a phone and a tablet (AD-52);
  the board side (`packages/core/src/board/side.ts`, AD-55) and the screen (`app/src/screens/board/`). So a browser check of the
  web build runs the code the phone runs; what only a device shows is the web view itself (`maestro/board-webview.yaml`, iOS and Android).
- The transport: `@aiwb/conn` (shared Client) + one transport per platform (AD-20 to AD-22); on the desktop the bridge
  `desktop/preload.js` + the unchanged main process (`ipcface.js`, `lib.js`, `main.js`). The window still loads the old
  page by default (D2 is not done: `desktop/lib.js pagePath`); the app's web build is what `AIWB_PAGE` points at.
