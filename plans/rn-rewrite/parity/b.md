# Parity report, area B: the chat view

The 235 rows of area **B** of `parity-inventory.md` (B.1 to B.14), in the inventory's order, against the tree of `rn-sweep` at `10e3c30` (first read at `b13110e`). Written by
package `rn-sw-parity-b` by reading: the check files (their first comments, their flags and their `fail()` / `expect()` lines), the unit tests' names, the
package notes (`s4` to `s10`, `k5`, `v1`), `app/e2e` and `web/e2e`. Nothing was run. The form is `parity/README.md`'s.

**Notation.** `d`, `t`, `p` are the viewports a check runs at (its own `viewports` line). `core/test/` is `packages/core/test/`. `app/test/`, `web/test/`
and `e2e/<name>[APP]` (the free e2e script driving the new build: `APP=1`; `remotechat` also with `VIEWPORT=phone`) are as in the README. A unit-test name cut with
"…" is a prefix, as in the inventory; every name was looked up in the file named. "Was `none`" says the old page had no test of the row. *Unshown: …* in a note is a
clause of a `yes` row that nothing automated shows.

**`pending`** is the value the sweep's brief asks for a row that depends on a flag of a check the sweep is turning on (or on the package that puts the @ list and the
quote float on the overlay stack). It is a fifth value besides the README's four; the note names the check and the flag. The flags that were still `false` at `10e3c30`
and touch area B (after the merge of `ec2d958`, which removed the AAC flags): `P7.1` `CARDS`, `RAIL`, `USAGE`; `IM3.5` `TREE`; `SEC.10` `INSERT_POPUP`; `SEC.7-drop` `SIDEBAR`; `SEC.6`
`CHAT_VIEW`; `A2.4-popups` `USAGE`; `SEC.9` `BOARD`. A row is `pending` only where the flag's part is a clause of the row; the others name the flag in their note and are `yes`.
