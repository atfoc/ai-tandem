# Parity of area C, the composer: text, board references, quotes, images, drafts, choices, prompt library

Written by package `rn-sw-parity-c` of the integration sweep, by reading (no check, test or build was run); the rows it left `yes, unshown` or `partly` were then taken by package `rn-sw-gaps-c`, which added their proofs (each run, and each made to fail once on purpose) and changed those rows. One row for each of the 237 rows of
area C of `plans/rn-rewrite/parity-inventory.md` (C.1 to C.11), in its order, in the form `parity/README.md` asks for. Read with it: the new
checks in `web/dev/checks-app/`, the package notes `k3-composer.md`, `k4-images.md`, `k5-quotes.md`, `s7-subagents.md`, `s11-library.md`,
`p1-sheets-keyboard.md`, `n3-keys.md`, `v3-composer-chips.md`, `d-e2e.md`, and `LOOSE-ENDS.md`. Where a row is "shown by" a check, the check file
was opened and the failure line (or the section) that proves the row is named, not only the ID.

**Notation.** `ID@d,t,p`: a check of `web/dev/checks-app/` at the viewports of its own `viewports` line (d desktop, t tablet, p phone).
`pc/` is `packages/core/test/`, `at/` is `app/test/`, `wt/` is `web/test/`. `e2e/<name>[APP]` is a free script of `web/e2e` on the new build
(`APP=1`, desktop viewport; the same assertions as on the old page). `dev/reallibrary-app.mjs` is the library's script on two real servers.
`maestro/…`, `xcuitest/…`, `adbkeys/…` are in `app/e2e/`. A quoted string after a check is the start of one of its failure lines (what it
says when the row does *not* hold) or of its own name for the step.

**How the proofs were weighed.**
- `wt/` tests are the old page's unit tests that were not moved by F2. Those cited here import only `packages/core/src` (they run with
  `cd web && npm test`) and prove core code, which the new build shares. They are listed at the end: **they are deleted with the old page at R1**
  (architecture §11, AD-81) unless they are moved to `packages/core/test/` first.
- Many of those tests also read the old page's *source* (`src("Composer.tsx")`, `ChatChoices.tsx`, `RefInput.tsx`, `ChatView.tsx`) or render
  `Library.tsx`, `ChatView.tsx` and `Composer.tsx` from `web/src` (`chatchoices`, `chatserver`, `remotechat`, `newchat`, `librarypopups`, `sectionviews`,
  and single tests of `insert`, `chatimage`, `sendend`, `drafts`, `sectionstorage`). **Those prove the old page, not the new build, and are not
  counted as proof.** A row whose only old proof was one of them has a check of the new build in "Shown by", or is `yes, unshown` with the test it needs.
- `wt/actions.test.ts` and `wt/keptpage.test.ts` drive core's state through a stand-in of the old composer's wiring, not through the new
  `Composer.tsx`; the rows that rest on them say so in their note.
- Rows `partly` have a part of their behaviour with no proof or deliberately different; rows `yes` may carry an "Unshown:" clause for an incidental
  detail no automated test reads (45 rows, listed at the end).
