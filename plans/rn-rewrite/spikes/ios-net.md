# Spike: the native transport on iOS (pinned TLS, HTTP/2, a long event stream)

Goal 4.6 and the first rows of risk 9. Branch `rn-spike-ios-net`, code in `spikes/ios-net/`. Everything below was
measured on the **iOS simulator** ("iPhone 17", iOS 26.3) against a **scratch Go server** (never the user's on 4748).
**Nothing was run on a physical device**; see "What this does not prove".

## Verdict

| # | Point | Verdict |
|---|---|---|
| 1 | Connector: accept the certificate iff the SHA-256 of its leaf equals the pin, refuse before any request byte, `cert_changed`; read a fingerprint without trusting | **GO**, with one condition: `NSAllowsArbitraryLoads` for servers reached by a dotted DNS name (below) |
| 2 | HTTP/2 negotiated (`networkProtocolName == "h2"`) | **GO** |
| 3 | A request with headers, body and a response size limit | **GO** |
| 4 | The event stream as text chunks to JS, parsed in JS; cancel/close | **GO** |
| 5 | Memory over a 20 minute stream | **GO** for 20 minutes (31 → 35 → 35 MB footprint); hours not measured, and the volume was small |

Overall for the transport: **GO**. One finding changes the plan (ATS, point 1) and several things the real implementation
must do differently are listed at the end.

## Versions

Expo SDK **57.0.28** (`expo` ~57.0.28, `expo-modules-core` 57.0.22), React Native **0.86.3**, React 19.2.3, Hermes,
TypeScript 6.0.3, template `blank-typescript`. Xcode 26.3, iOS simulator runtime 26.3.1, macOS 15.7.9, Node 24.3.0,
Go 1.25.1, CocoaPods 1.16.2. The app is an Expo **dev build** (`npx expo run:ios`, native project generated by prebuild,
not committed; not Expo Go) built in **Release** so the JS bundle is inside the app and no Metro is needed. The Swift
module is a **local** Expo module (`spikes/ios-net/app/modules/aiwb-net`, autolinked, Expo Modules API), no dependency
beyond `ExpoModulesCore`; CryptoKit and Security for the hash and the trust.

## How to run it (repeatable, no clicking)

```sh
node spikes/ios-net/run.mjs                      # builds server + app, runs 28 checks on the simulator, about 1 minute
node spikes/ios-net/run.mjs --skip-build         # the same without rebuilding the app
node spikes/ios-net/run.mjs --minutes 20         # holds the stream 20 minutes, changes a board twice a second, samples memory
```

`run.mjs` starts a scratch server (its own home and a free port, as `web/e2e/lib/rig.mjs` does), the stand-ins (below), builds
and installs the app, launches it with its configuration in `SIMCTL_CHILD_AIWB_CONFIG`, and reads what the app logs from
`Documents/aiwb-spike.log` in the simulator's data container (the same lines go to `NSLog` and are also captured with
`simctl spawn … log stream`, kept as `oslog.txt`). It exits 0 when every check passed and the tripwire counts hold, and
stops everything it started. `scratch.mjs` starts/stops the scratch server alone. The simulator is chosen with `--udid`
(default the one assigned to this spike). The last full run: `28 check lines, 0 failed`
(`ios-net-evidence/checks-app.log`).

The stand-ins started by the runner: two TLS servers with a certificate that is not the server's (the **tripwires**: they
count the bytes written to them after the handshake); a plain HTTP server; a closed port; two h2 servers whose
certificates are valid 365 and 3650 days; an h2 server whose event stream goes silent after two events.

## The native module as built

`import { openSession, readCertificate, … } from './modules/aiwb-net/src'`; the raw module is `Native`.

Native functions (`ios/AiwbNetModule.swift`):

| Function | Does |
|---|---|
| `readCertificate(host, port, timeoutMs): Promise<string>` | one handshake that takes any certificate, returns the **leaf's** fingerprint (`AA:BB:…`, uppercase, 32 pairs, the format of `desktop/conn/tls.js fingerprintOf`) and **cancels the authentication challenge**: no request is written |
| `openSession(host, port, pin): Promise<sessionId>` | makes a `URLSession` (ephemeral, no cache, no cookies, no credential storage, no system proxy, TLS ≥ 1.2, 24 h request timeout) whose delegate judges the certificate; an empty pin rejects with `fingerprint` and nothing is dialed. **Nothing is dialed yet**: URLSession connects at the first request |
| `request(sessionId, requestId, {method, path, headers, body \| bodyBase64, maxBytes, limitMs}): Promise<{status, headers, body(base64), protocol, reused}>` | the whole answer; a body above `maxBytes` is not read further and rejects `too_long`; `limitMs` bounds all of it (`timeout`) |
| `stream(sessionId, requestId, {…, headersMs}): Promise<{status, headers}>` | resolves at the headers; text arrives as events `onStreamChunk {requestId, text}`; `onStreamEnd {requestId, error, protocol, reused, bytes}` fires once at the end (`error` is `""` for the server's clean end) |
| `cancel(sessionId, requestId)` / `closeSession(sessionId)` | cancel one request or stream (its promise or `onStreamEnd` carries `aborted`) / end the session |
| `normalFingerprint(s)`, `selfTestUtf8(text)`, `log(line)`, constant `env` | the pin's normal form (port of `list.js`); a self-test of the UTF-8 chunker; spike plumbing |

The trust rule (the only place a certificate is judged): in `urlSession(_:didReceive:completionHandler:)`, take the **leaf**
of `SecTrustCopyCertificateChain`, SHA-256 its DER, compare with the normalized pin. Equal → `.useCredential(URLCredential(trust:))`;
anything else → remember `{cert_changed, presented, pinned}` and `.cancelAuthenticationChallenge`. The system's verdict on the
certificate (no root, 10 years of validity, a name that does not match) is never asked. The name of the certificate is not checked
(as on the desktop).

Failures reject with a JSON message `{code, detail, fingerprint, pinned}`. `src/index.ts` maps it to **`Problem`** (outcome =
`fingerprint | cert_changed | tls_error | not_https | refused | name_not_found | no_route`, the names of `desktop/conn/outcomes.js`)
or **`NetError`** (`timeout | reset | too_long | closed`) or an `AbortError`, the same classes `session.js`/`tls.js` throw. JS has
`Session.fetch(opts)`, `Session.stream(opts, onChunk) → Stream {status, headers, ended, cancel()}`, `Session.close()`, and
`src/sse.ts`, a line-for-line port of `EventReader` (limit `MAX_STATE`).

Native decodes UTF-8 itself and holds back an incomplete trailing sequence, so JS only ever sees whole characters
(check `4-utf8-chunker-every-cut`: 1890 cuts of a string with 2-, 3- and 4-byte characters and a combining mark, none broken).

## Evidence per point

### 1. Connector (GO)

Lines from `ios-net-evidence/checks-app.log` (final run):

```
CHECK 1-read-certificate PASS fingerprint A8:D5:…:5F:71 equals the one the server printed
CHECK 1-pin-accepted-hello PASS 200 {"app":"ai-whiteboard","featureLevel":6,"instanceId":"…","version":"dev"}
CHECK 1-pin-accepted-in-lower-case-without-colons PASS a pin in any normal form is accepted
CHECK 1-no-pin-is-outcome-fingerprint PASS Problem fingerprint
CHECK 1-wrong-pin-is-cert_changed PASS Problem cert_changed presented=A8:D5:…:5F:71 pinned=00:D5:…:5F:71
CHECK 1-wrong-pin-on-the-stream-too PASS Problem cert_changed
CHECK 1-tripwire-wrong-pin-refused-before-any-byte PASS Problem cert_changed presented=17:D2:…:C1:28
CHECK 5-error-outcomes PASS refused, not_https, name_not_found
```

**Refused before any request byte.** The app sent a POST with a body and the secret header to a TLS server with another
certificate, holding the server's pin. The tripwire counted, after the handshake: `connections 0, appBytes 0,
HTTP/2 prefaces 0` (`tlsClientErrors 2`: that request and the `readCertificate` of the next check, both client aborts in
the handshake). The control (same tripwire kind, the app holds its pin) counted `appBytes 2772, prefaces 9` (URLSession
retried the dropped GET nine times), so the tripwire does see what is written. `readCertificate` against the tripwire also
left no byte. A wrong pin is never retried by URLSession.

**Dotted DNS names need `NSAllowsArbitraryLoads` (the finding).** With a pinned self-signed certificate, connecting by IP
address works and `localhost` works under Expo's default ATS (`NSAllowsArbitraryLoads=false`, `NSAllowsLocalNetworking=true`),
but connecting by a **dotted DNS name** (tested: `localtest.me`, which resolves to 127.0.0.1; the server's certificate lists
it) fails in the TLS layer right after the delegate said `.useCredential`: `NSURLErrorDomain -1200`, stream error `-9802`.
Matrix, same code, same server, measured by reading the installed app's Info.plist (`plutil`, printed by `run.mjs`):

| `NSAppTransportSecurity` in the installed app | IP / `localhost` | dotted name |
|---|---|---|
| Expo default `{Arbitrary: false, LocalNetworking: true}` | pass | **fail -9802** |
| `{Arbitrary: true, LocalNetworking: true}` | pass | **fail -9802** (LocalNetworking makes ATS apply again) |
| `{Arbitrary: true}` | pass | pass |

With `{Arbitrary: true}` alone, three variants of the trust hook all pass: plain `.useCredential`; with the leaf set as the only
anchor; with `SecTrustSetExceptions`. So the ATS key is the cause; no trust-object trick replaces it. Certificate shape did not
matter (365 and 3650 day certificates both pass under the permissive ATS; the server's 10-year certificate makes the system
evaluation say "exceeds maximum temporal validity period", irrelevant because the system's verdict is not asked). The cost is
App Store review: `NSAllowsArbitraryLoads` needs a justification ("connects to user-chosen servers")
`[not verified]`. Narrower options (`NSExceptionDomains` with `NSIncludesSubdomains` for broad suffixes) were not tried.
Servers reached by IP (the common LAN case) and `.local`-less unqualified names need nothing. `app.json` sets
`ios.infoPlist.NSAppTransportSecurity = {NSAllowsArbitraryLoads: true}` and replaces Expo's default dict.

### 2. HTTP/2 (GO)

```
CHECK 2-http2-negotiated PASS networkProtocolName=h2 reusedConnection=true
CHECK 4-event-stream PASS … stream protocol=h2 reusedConnection=true
```

The first request's metrics say `h2` (`HELLO … protocol=h2 reused=false`); the second request and the event stream reuse the one
connection (request and stream at once on one h2 connection: the rename during the stream, check `4-event-stream`). A stream's
metrics arrive only when it ends, so its protocol is read at the end (`STREAM-END protocol=h2 reused=true`). The tripwire's
ALPN list shows `h2` for the connections that did the handshake.

### 3. Requests (GO)

```
CHECK 3-authenticated-chats-list PASS 200 state with chats=0 boards=0 (898 bytes, protocol h2)
CHECK 3-secret-refused-401 PASS 401 {"error":"unauthorized"}
CHECK 3-size-limit PASS NetError too_long for a 100 byte limit on /api/state; the session is usable after it
CHECK 3-post-with-headers-and-body PASS 200 board b_… named spike-ünïcode-✓-日本語
CHECK 3-timeout PASS NetError timeout after 1.5 s on a never-ending body
CHECK 3-cancel-a-request PASS AbortError 707 ms after the call, the signal fired at 700 ms
```

The "chats list" is `GET /api/state` (it has `chats`; the scratch server has no agents so no chat could be made: it is empty,
the parsing of a non-empty one is not exercised). `X-AIWB-Secret`, `-Client` and `-Level` are sent on every call. A limit hit
cancels the h2 stream; the connection stays usable.

### 4. Event stream (GO)

```
CHECK 4-event-stream PASS order=hello,snapshot firstAt={"hello":6,"snapshot":6,"board":68} events=3 pings=1 chars=1276;
     cancel ended in 1 ms as AbortError; stream protocol=h2 reusedConnection=true
CHECK 4-silent-stream-ended-by-a-js-watchdog PASS … the watchdog fired 3011 ms after the open and the stream ended 2 ms after cancel();
     the h2 connection was reused afterwards
CHECK 4-server-stops-ends-the-stream PASS the stream ended 75 ms after the server was stopped, cleanly (the server closed the stream)
```

The stream arrives incrementally (a board event 68 ms after the rename that caused it; the ping, a `: ping` comment line every
20 s, is seen). `hello` then the snapshot, as `conn.js` expects; `EventReader` in JS parsed all of it. Cancel is immediate.
A silent stream is not ended by URLSession (its timeouts are set to a day), so the **watchdog is JS's**, as the goal says
(`silence`); the check proves a JS timer plus `cancel()` ends it and leaves the connection usable. A server that stops ends
the stream with a clean end, not an error (as Node does).

### 5. Memory over a 20 minute stream (GO for 20 min; weak on duration and volume)

`node spikes/ios-net/run.mjs --minutes 20`: the stream was open 1290 s (21.5 min), one open, no reopen; the script changed a
board 2543 times (about 2 events/s) and the stream carried 64 pings; JS received 2545 events and 399,315 characters and parsed
each. Memory of the app process (the simulator app is a Mac process):

| | start (13 s in) | middle (10:00) | end (20:00) |
|---|---|---|---|
| `footprint` (physical footprint) | **31 MB** | **35 MB** | **35 MB** (peak 36 MB) |
| `ps -o rss` | 211 MB | 164 MB | 161 MB |

`ps rss` is mostly mapped system frameworks and fell by 50 MB in the first two minutes as startup pages were reclaimed; it
then moved between 157 and 164 MB for the 19 minutes after, with no trend (`long20-rss.csv`, a sample per 30 s). The footprint
rose 4 MB between start and the middle, and not at all in the second half. By eye this is a plateau; there is no leak of
the size of the data (about 18 KB/min arrived, so a leak of the stream's text would have been under 0.4 MB; this test is **not
sensitive to a small per-event leak**) . What would leak per event in this design is the JS-side string and the
event-bridge, both exercised 2545 times. Detail: `ios-net-evidence/long20-*`.

## Problems met and how they were solved

1. **Numbers from JS are `Double` in Swift.** `options["maxBytes"] as? Int` was silently nil, so limits and timeouts were ignored
   (the first run hung on the never-ending body). Fixed with an explicit number reader. A real implementation should use typed
   `Record` options (Expo Modules `Record`/`Field`), which would have caught it.
2. **Error text.** A rejected promise's message is wrapped (`FunctionCallException … Caused by: AiwbNetError: {json} (at …swift:31)`);
   the JSON is cut out between the first `{` and the last `}`. A real module should use a typed exception with a stable `code`.
3. **ATS and dotted names** (above): found by a matrix of Info.plist variants. A trap while doing it: Expo's `prebuild` does not
   remove keys it no longer sees in `app.json`, and `grep -A3` hid the `NSAllowsLocalNetworking` key that made one variant fail,
   so the plist of the **installed** app is now printed by the runner.
4. **The UTF-8 chunker** (a character cut between two chunks must not break) is never exercised by a real server whose chunks fall on
   event boundaries, so `selfTestUtf8` cuts a string at every offset. It passed at once.
5. `.gitignore` of the generated app ignored `ios/` and with it the Swift source in `modules/aiwb-net/ios/`; anchored to `/ios/`.
6. The template adds `LICENSE` and an `AGENTS.md`; removed.

## What the real implementation should do differently

- **Fold "open a session" into the first request.** URLSession connects lazily, so the shared Connector's `openSession` cannot
  fail with `refused`/`cert_changed` by itself. The Session port should be `connect(): hello`, with the native failure codes
  mapped as above, so the Conn sees the same outcomes in the same step. (An eager connect would need a probe request.)
- **Scope the "mismatch" per connection, not per session.** The spike keeps one `mismatch` in the session (cleared on the next
  accepted pin) and blames it on whichever task fails next; keep it per task/challenge.
- **Decide the ATS question first.** `NSAllowsArbitraryLoads` is needed for any server named by a dotted DNS name (Tailscale
  names, `*.example.com`, a VPN host name such as the user's own). If review or policy refuses it, the app can only reach IPs and
  undotted/`.local` names. Check on a device and with the account used for distribution.
- **Bodies as bytes, not base64.** `request` returns the body as base64 text across the bridge (+33 %, a JS decode). Fine for JSON;
  for pictures use Expo's typed-array support or a file path.
- **Typed options and errors** (`Record`, a coded `Exception`), a per-request header-time timer for plain requests, and tests of
  the Swift in an XCTest target in addition to the on-device run.
- **Back pressure.** Chunks go to JS as one event each with no flow control. At this rate irrelevant; for a busy server (chat
  tokens, many boards) batch chunks per ~50 ms natively.
- URLSession **retries an idempotent request on a dropped connection by itself** (9 attempts seen against the tripwire); the Conn's
  own back-off should not be doubled by it. Use `URLSessionConfiguration`'s `waitsForConnectivity = false` (set) and decide whether
  non-idempotent calls (POST) are safe (they were not retried).
- `connectionProxyDictionary = [:]` makes the session ignore system proxies, as Node's `net.connect` does; a user who needs a
  proxy for the server has none, as on the desktop.

## What this does not prove (not verified)

- **A physical device.** The simulator uses the Mac's network stack and its own memory accounting; iOS's jetsam limits, power
  management and cellular/VPN paths are not covered. The **local network permission prompt** (`NSLocalNetworkUsageDescription`
  is set in the plist) and its refusal state were not exercised; the simulator never prompts.
- **Hours.** 21 minutes at 2 events/s and 18 KB/min. The goal says "held for hours".
- **Background and suspension**: the app was in the foreground throughout.
- **IPv6 literals**, a name that resolves to several addresses, a certificate rotated during a connection, a stalled TCP
  connection with no FIN (the JS watchdog was tested on a stream that stays open but silent, which is the same case from the
  stream's side).
- **A non-empty chats list**, and large bodies (pictures, scenes of megabytes).
- **App Store acceptance** of `NSAllowsArbitraryLoads` for this purpose.
