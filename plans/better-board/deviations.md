# Departures from goal section 7

Each entry: what, why.


- **7.4, the window's route and event (architect).** What: instead of one `POST /api/boards/{id}/sync` and a `sync` event, a session has its own routes `POST /api/tl/{id}/open|sync|close` and events `tl_sync`/`tl_closed`, sent to the session's window alone (`Bridge.SendTo`), not to the board's followers. Why: an explicit open gives Go a session id to tag messages with and a moment to start the board host; a follower event would echo every message back to its sender and reach windows that do not show the board (design 2.2, 2.3).
- **7.1, "growing out of packages/headless" (architect).** What: the board host is a separate package and process, not the headless writer extended; it reuses the headless writer's code (config, conn client, memstore) and its Go manager (a second instance). Why: old boards must not change (goal 4.3), and the two processes have different lives (design 1.3).
- **7.5, the agent as a peer (architect).** What: neither of 7.5's two options exactly. Each room has one editor in the host that is not a sync peer; an `apply` sets it to the room's records, runs the ops and writes the diff to the room in one storage transaction. The agent's marker is a custom message, not a tldraw presence. Why: a synchronous, atomic `apply` with save-before-answer, no second store per room, and the marker goal 3.4 asks for (design 7.4, 8).
- **7.7, who writes the snapshot (architect).** What: the board host decides when to save, and Go writes the file on the host's `PUT /api/tl/{id}/snapshot`, accepted only from the current host. The file is `snapshot.tl.json`. Why: one owner of the board folders (no race with a delete), and an old dying host process cannot overwrite a new one's save (design 4.2).
- **7.6, refs (architect).** What: a `create`'s `ref` is kept on the element as a key (`meta.key`) and can be used in later calls, and `read_board` is JSON Lines. Why: agents need stable names across calls, as old boards' keys give them (design 7.1, 7.3).
- **7.6, the `TlElement` type of design 7.3 (T1a).** What: the type's tail `Partial<Omit<CreateSticky & CreateShape & CreateText & CreateConnector & CreateFrame, …>>` is written in `packages/board-tl/src/model/terms.ts` as "each field of any create op, optional, with the union of its types" (so `color` is `StickyColor | Color`). The JSON lines are unchanged. Why: as written, the intersection is `never` (the ops' `type` fields conflict), which made every style field `undefined`, so no element with a colour or a size could be typed.
- **7.2, the sticky (spike bb-spike-ui).** What: a custom `sticky` ShapeUtil (square, its own colour style prop `aiwb:sticky-color`, shrink-to-fit text stored as `fitted`), the fallback 7.2 names, not tldraw's `note`. Why: 5.6's `note` grows (`growY`) instead of shrinking its text, shrinks the font only for long words, does both in private methods, resizes only by scale and hard-codes its paper look (spike-ui.md D).
- **7.3, the select tool overrides go beyond the idle / pointing-canvas pan (spike bb-spike-ui).** What: besides drag-to-pan from `pointing_canvas`, the override (a) clears the selection on pointer up instead of down, so a pan keeps it; (b) hands a pointer down inside an unfilled shape to `pointing_shape`, so a drag there moves the shape (tldraw treats a hollow shape's inside as canvas); (c) replaces `idle`'s double-click on empty canvas to create a sticky (on the second release, so a pinch is not read as a double-tap), with tldraw's text-on-double-click off by option. Why: Miro's behaviour (goal 3.1, 3.3); all through subclasses of tldraw's own states, no patch (spike-ui.md C).
