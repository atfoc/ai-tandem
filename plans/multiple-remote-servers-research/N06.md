# N06: an API client that follows and acts on chats without taking the active-client role

The decision "API clients: no take-over" works. A scratch patch of 5 files (+155 −6) adds a second handler
that tags its requests as an API client's, an event stream for such clients that is never active and never
pending, and a guard that lets them call the chat routes without the role. Go tests in the scratch copy, with
the existing test environment and a stand-in agent, ran scenario A (a page is active) and scenario B (no page):
both pass. The page was never superseded and got no `release_request`, its scene, draft and group-order saves
were accepted during and after, two API clients and the page saw the same chat events, and the board-tool
`rpc` went to the page only. With no page, create, send, permission answer, interrupt and the turn's events
work; a board tool answers at once with the existing "the board isn't open" error. All existing tests of
`internal/editorbridge`, `internal/server` and `internal/chats` pass unchanged on the patched copy.

## S1. Telling an API client from the page, and its stream

**Answer.** One context value set by a second handler is enough as the marker; the stream is one new method on
the bridge plus a loop over API clients in `Broadcast`. The active/pending code is not touched at all, which is
why no take-over can happen: an API client is never put in `b.active` or `b.pending`.

- Today every stream goes through `ServeSSE`, which makes the caller active, or pending with a
  `release_request` to the active one and a promotion after 3 s **[code: `internal/editorbridge/bridge.go:92-116`,
  `279-302`]**. `Broadcast` and `Call` write to `b.active` only **[code: `bridge.go:190-200`, `204-220`]**.
- The marker **[patch]**:
  ```go
  // internal/server/server.go
  func (s *Server) Handler() http.Handler { return guard(s.Bridge, s.Port, s.mux()) }
  func (s *Server) APIHandler(port int) http.Handler {
      s.Bridge.ObserverWants = func(typ string) bool { return apiEventTypes[typ] }
      h := guard(s.Bridge, port, s.mux())
      return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
          h.ServeHTTP(w, r.WithContext(context.WithValue(r.Context(), apiClientKey{}, true)))
      })
  }
  mux.HandleFunc("GET /api/events", func(w http.ResponseWriter, r *http.Request) {
      if isAPIClient(r) { s.Bridge.ServeObserver(w, r); return }
      s.Bridge.ServeSSE(w, r)
  })
  ```
- The stream **[patch]**:
  ```go
  // internal/editorbridge/bridge.go
  observers     map[*client]struct{}       // in Bridge, guarded by mu
  ObserverWants func(typ string) bool      // nil = every type

  func (b *Bridge) ServeObserver(w http.ResponseWriter, r *http.Request) {
      ...
      b.mu.Lock()
      b.observers[c] = struct{}{}
      b.sendLocked(c, event{"type": "hello", "active": false, "waiting": false, "api": true})
      b.snapshotLocked(c)                  // the same snapshot the page gets
      b.mu.Unlock()
      defer func() { b.mu.Lock(); delete(b.observers, c); b.mu.Unlock() }()
      b.pump(w, r, fl, c)                  // the write loop, moved out of ServeSSE unchanged
  }
  // in Broadcast, after the send to b.active:
  if len(b.observers) == 0 || (b.ObserverWants != nil && !b.ObserverWants(typeOf(ev, msg))) { return }
  for c := range b.observers { b.sendRawLocked(c, msg) }
  ```
- Why the three role events cannot reach an API client **[code]**: `release_request` and `superseded` are sent
  with `sendLocked` to `b.active` / `b.pending` (`bridge.go:105-110`, `295`), `rpc` with `sendRawLocked` to
  `b.active` in `Call` (`bridge.go:211-219`); none of them goes through `Broadcast`. So they stay away from
  API clients without any filter.
- **[run]** `TestAPIClientWithActivePage`: the API client's stream opens with `[hello snapshot]`, hello is
  `map[active:false api:true type:hello waiting:false]`. After a 3.5 s sleep (longer than the handover delay)
  `IsActive("A")` is true, `IsActive("L1")` and `IsPending("L1")` are false.
- A slow API client: a full 4096-message buffer closes that client's stream only (`sendRawLocked`,
  `bridge.go:334-343`), the same rule as for the page **[code]**; not exercised **[not run]**.
- The `client` query parameter is not needed for an API client and is not compared with anything; an
  `X-AIWB-Client` header on the API handler is ignored **[patch]**.

## S2. Chat routes without the role

**Answer.** One branch in `guard`. The role check lives in a single place (`guard.go:32`), not in the
handlers, so no chat handler changes. The prototype gives an API client an allow-list: every GET under `/api`,
and every non-GET under `/api/chats` except `…/draft`. Everything else answers 403 `not_for_api_clients`.

```go
// internal/server/guard.go, in guard(), before the active-client check
if isAPIClient(r) {
    if !apiClientMay(r) { writeError(w, http.StatusForbidden, "not_for_api_clients"); return }
    next.ServeHTTP(w, r); return
}
func apiClientMay(r *http.Request) bool {
    p := r.URL.Path
    if !strings.HasPrefix(p, "/api/") { return false }                   // no client files
    if r.Method == http.MethodGet || r.Method == http.MethodHead { return true }
    if p != "/api/chats" && !strings.HasPrefix(p, "/api/chats/") { return false }
    return !strings.HasSuffix(p, "/draft")
}
```

**[run]** (API client = no `X-AIWB-Client` header at all, on the API handler):

```
POST   /api/chats                      → 200   (plain chat, and a chat on a board)
PATCH  /api/chats/{id}  {cwd}          → 200   PATCH {name} → 200
POST   /api/chats/{id}/messages        → 200 {"branch":"main","ok":true}
POST   /api/chats/{id}/permission      → 200   POST …/interrupt → 200
GET    /api/chats/{id}/items, /tree, /api/chats/{id}, /api/state → 200
POST   …/open, …/archive, …/unarchive → 200    DELETE /api/chats/{id} → 200, then GET → 404
PUT    /api/chats/{id}/draft           → 403 {"error":"not_for_api_clients"}
PUT    /api/boards/{id}/scene, POST /api/boards, POST /api/groups → 403
POST   /api/rpc-reply, POST /api/client/release → 403        GET / → 403
loopback handler, header X-AIWB-Client: L1 (not active), POST …/interrupt → 409 (unchanged rule)
```

- The stand-in agent recorded `send,decide p1 true,interrupt`: the three calls reached the agent **[run]**.
- Not called in the tests **[not run]**: fork, label, send with `target` (a new branch), `PATCH {group}`
  (move), `PATCH {model, effort}`, subagent routes, `/context`. They pass the same guard branch **[code]**.
- The allow-list lets an API client read everything a GET gives: `/api/state`, board scenes, `/api/dirs`,
  `/api/usage/…`, `/api/mcp/status`, run routes **[code: `server.go` GET routes]**. Narrowing it is a change to
  `apiClientMay` only.

## S5. Other events on an API client's stream

**Answer.** Unfiltered, the stream carries everything `Broadcast` sends. Leaving types out is a filter in one
place (`Broadcast`), not a change at the emitters. The snapshot is a second place: it is the whole state.

- **[run]** `TestAPIClientUnfilteredStream` (`ObserverWants = nil`; the page makes a group, a board, renames
  it, a chat, a turn, deletes the board):
  `unfiltered API stream carried: [board board_removed branch_state chat chat_items defaults groups hello server_stopping snapshot tree]`
- All broadcast types **[code]**: `groups`, `defaults` (`internal/app/app.go:114`, `120`;
  `chats/manager.go:1455`; `runs/service.go:902`), `board`, `board_removed` (`internal/boards/boards.go:174`,
  `226`, `282`), `chat`, `branch_state`, `chat_items`, `tree`, `sub`, `sub_items`, `chat_removed`
  (`internal/chats`), `catalog` (`cmd/ai-whiteboard/main.go:385`, `399`, `413`), `run`, `run_removed`,
  `run_activity`, `run_detail` (`internal/runs/events.go:20`, `26`, `engine.go:855`, `run.go:249`),
  `server_stopping` (`bridge.go:259`). The test environment has no run service and probes no catalog, so run
  and `catalog` events were not seen on a stream **[not run]**.
- The filter in the prototype **[patch]**: `apiEventTypes = {chat, chat_items, chat_removed, branch_state,
  tree, sub, sub_items, catalog}`. With it, in scenario A the API streams got no `board`, `groups` or
  `defaults` although the page got `board:1 groups:1` **[run]**.
- How the type is read: every emitter but runs passes a `map[string]any`, so the type is a map lookup; the run
  events are structs, for which the prototype parses the marshalled JSON once more to read `type`
  **[patch, code]**. That second parse of run events is the only cost found; not measured **[not run]**.
- `chat` and `branch_state` events of chats made by the server's own page, and `chat_items` of all user chats,
  go to every API client: there is no per-chat or per-owner subscription (N04 S1) **[code]**. An API client
  filters by chat id on its side.
- The snapshot sent on connect has `boards catalogs chats dataDir defaultCwd defaults groups home runs states`
  **[run]**. Trimming it for API clients needs a second snapshot function (`bridge.go:37`, `app.Snapshot`), a
  few lines, not done **[not run]**.
- `server_stopping` is filtered out; `StopAndFlush` waits only when a page is active (`bridge.go:247-253`), so
  an API client just sees its stream end when the server exits **[code]**.

## S6. "An API client's chats record no sticky defaults on that server"

**Answer.** As a property of the chat it is one condition, in `recordDefaults`, plus a flag on the chat set
where the chat is made. As a property of the caller it would be more: a parameter through three manager calls.
The sentence in the plan should say which it means.

- Defaults are written for chats in one function, `recordDefaults` (`internal/chats/manager.go:1444`), called
  from two places: the first message (`manager.go:1243-1246`) and a configure (`manager.go:1401-1403`)
  **[code]**. Create only reads them (`manager.go:779-781`).
- The prototype **[patch]**: `ChatMeta.API bool` (`json:"api,omitempty"`), set by
  `CreateFor(agent, group, board, isAPIClient(r))`; and
  ```go
  func (m *Manager) recordDefaults(c *Chat, …) {
      if topOf(c).meta.API { return }   // set at creation, never changed
  ```
- **[run]** In scenarios A and B the defaults were compared before and after the API client's configure and
  first send: unchanged (asserted). `TestAPIClientDefaults`:
  ```
  API client's chat, the page configured and sent: defaults unchanged, 0 defaults events at the page
  page's chat, the API client configured and sent: defaults changed true, 2 defaults events at the page
  defaults after: {"last":{"cwd":"…/004","byAgent":{"claude":{"model":"sonnet","effort":"high"}}},"groups":{"__ungrouped__":{…}}}
  ```
  So with the per-chat flag, an API client that configures a chat the page made still writes that server's
  defaults. Closing that needs the caller passed into `ConfigureOf`, `SendBranch` and `SendToBranch` (three
  signatures and their callers) **[code]**.
- More places a real change must look at **[code]**:
  - A fork makes a new chat whose record is built without the flag (`internal/chats/fork.go:271`); it would have
    to copy it. A fork never records model or effort (`defaultsChoice`, `manager.go:1460-1465`), but its folder
    could be recorded **[inferred]**.
  - A chat on a run never records (`manager.go:1244`, `1401`), and `CreateOnRun` (`owned.go:262`) needs nothing.
  - An API client's chat starts from that server's defaults: its folder is that server's `last` folder or
    `DefaultCwd` until the API client sets it with `PATCH {cwd}` **[code: `manager.go:779-781`]**.
  - The `defaults` event itself is not in the API stream filter, so nothing about defaults reaches an API client
    after the snapshot **[run]**.

func (b *Bridge) CloseObservers() {
    b.mu.Lock(); defer b.mu.Unlock()
    for c := range b.observers { b.closeLocked(c); delete(b.observers, c) }
}

**[run]** end of `TestAPIClientWithActivePage`: after `CloseObservers()` both API streams ended (EOF at the
client) within the 2 s the test allows, the page's stream stayed open and active, `Observers()` was 0, and a

here **[not run]** (N01 S5 ran a stream over HTTP/2 to its end by timeout only).

- `GET /api/chats/{id}/items` of a run agent's chat turns that chat's events on for the server (`Watch`,

## Implications (opinion)

- The decision can stay as written. The fallback "the local server takes the active role only on a user
  action" is not needed for chats: nothing found here requires the role. It would only matter if the design
  later wants board tools of a remote chat answered by the local page, which this decision excludes.
- The reason it is cheap is that the role check is in one place (`guard`) and the role events never go through
  `Broadcast`. A real change should keep both properties and say so in comments, since a later
  `Broadcast(event{"type": "rpc" …})` would leak to API clients unless the type filter stays an allow-list.
- The allow-list of routes is the real contract and belongs in the plan: which GETs an API client may read
  (the prototype allows all, including scenes, `/api/dirs` and `/api/state` with `home` and `dataDir`), and
  that drafts, boards, groups, runs, restart and the role routes are closed.
- Prefer the per-chat flag for defaults (one condition, persisted with the chat, covers the page acting on
  such a chat too) and copy it on fork. The flag is also the natural place to tell "chats made for another
  server" apart in that server's own page, if the plan wants to show or hide them.
- Send the snapshot on the API stream (as the prototype does) so that a reconnect after `CloseObservers` or a
  dropped buffer needs no separate `GET /api/state` and has no gap; trim it to chats, states and catalogs.
- `ObserverWants` is set inside `APIHandler` in the prototype; in a real change it belongs in the bridge's
  constructor so that it is fixed before any request.
