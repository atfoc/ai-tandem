# N07 — Prototype: an unstarted chat changes its agent, a chat is created with a given id, and the defaults work without "last used"

All three parts were built in a scratch copy of the Go server and run with Go tests; no server was started and no agent ran. **A works**: a chat is created with no agent in the request, `PATCH /api/chats/{id} {agent}` changes it any number of times before the first message, the first message starts only the agent chosen last with its model, effort and session id, and after it the change answers 409. **B works**: `POST /api/chats` accepts `id`, `agent`, `cwd`, `model`, `effort`; a repeat with the same id returns the existing chat (started or not) and makes and starts nothing; a bad folder or model answers 400 and leaves nothing behind. **C works with these changes**: `Defaults.Last` is gone, its four read sites read the ungrouped group, an old `state.json` merges `last` into the ungrouped group at load, and a sticky agent per group was added; 21 existing tests and one test helper had to be edited, all because they named `Last` (one also because the group entry now holds an agent). Neither fallback of the design is needed. The whole change is 298 lines added and 116 removed in 9 non-test Go files.

## S1. The agent is changeable before the first message

Works, and is cheap: about 40 lines in `ConfigureOf` plus one field. The complete list of what creation sets per agent is three things: model, effort, session id. On a run there is a fourth input (the run's model when the agent is the run's kind). Nothing else has to be undone.

**What creation sets per agent** (**[code]**): `Model`/`Effort` from `defaults.Resolve(…, a, …, m.catalog(a))` (`internal/chats/manager.go:781`); `SessionID` for Claude and pi only (`:791-793`, `internal/chats/owned.go:282-284`); on a run, the run's deep-tier model when `a == ri.Agent` (`internal/chats/owned.go:259-261`). Not per agent: the MCP token (`manager.go:789`; the caller's kind is read from the chat's meta at each call, `internal/chats/tokens.go:58-72`, so the token needs no change), the chat's folder, `chat.json`, the empty thread. `McpInstructionsSent`, the namer, the catalog event and the process are all first touched in `Send` (`manager.go:870,1255`).

**The patch** (patched `internal/chats/manager.go:1464-1516`):

```go
if req.Agent != "" {
    // The agent is fixed at the first message, and a branch's and a fork's is its source's.
    if c.meta.Locked || c.top != nil || c.meta.ForkedFrom != "" || c.ag != nil { unlock(); return ErrLocked }
    if !knownAgent(req.Agent) { unlock(); return badChoice{fmt.Errorf("unknown agent %q", req.Agent)} }
}
...
changed := req.Agent != "" && req.Agent != next.Agent
if changed {
    next.Agent = req.Agent
    _, mc := m.startChoice(m.GroupOf(next), next.Agent, ri)   // the same function creation uses
    next.Model, next.Effort = mc.Model, mc.Effort
    next.SessionID = ""
    if next.Agent == model.Claude || next.Agent == model.Pi { next.SessionID = uuid() }
}
mc, _, err := m.choose(next.Agent, …, req.Model, req.Effort)  // a model in the same request is checked against the new agent
```

The folder is kept (as a draft run keeps it, `internal/runs/service.go:691-698`). Creation without an agent: `CreateChat` takes the place's sticky agent (S4), on a run the run's kind (my choice; reported in Unknowns). `POST /api/chats` and `PATCH /api/chats/{id}` got the `agent` field (patched `internal/server/server.go:505-526,701-733`). `ErrLocked`'s text now names the agent.

**Run** — `TestN07AgentChangesUntilTheFirstMessage` (**[run]**, PASS), with three `agenttest.Fake` spawners; it asserts, in order:
- create with no agent → Claude, `sonnet`/`high`, a session id, the default folder;
- change to Cursor → `composer-2`/`high` (Cursor's catalog default), **no** session id, same id, token and folder, not locked;
- change to pi with `model:"pi/big", effort:"low"` in the same request → that model and effort, a **new** session id different from Claude's first one;
- naming the same agent again changes nothing in `chat.json` (session id included); an unknown agent and "Claude with pi's model" are refused (`ErrBadChoice`) with `chat.json` unchanged;
- before the message: `Spawns()` of all three fakes is 0, and the file list of the chat's folder is the same as at creation;
- the message: pi's `Spawns()` is exactly one with `Model "pi/big"`, `Effort "low"`, `SessionID` = the id set by the second change, `Resume false`; Claude's and Cursor's stay 0; the thread is `user text end`;
- after it: `{Agent: claude}`, `{Agent: pi}` (the same one) and `{Agent: cursor, Model: …}` all answer `ErrLocked`; `chat.json` unchanged.

Over HTTP, `TestN07AgentOverHTTP` (**[run]**, PASS): `POST {"group":"__ungrouped__"}` → 200, agent `claude`; `PATCH {"agent":"cursor"}` → 200; `PATCH {"agent":"nobody"}` → `400 {"error":"unknown agent \"nobody\""}`; after `POST …/messages` → `PATCH {"agent":"cursor"}` → `409 {"error":"agent, folder, model and effort are fixed once the chat has started"}`.

**What the code did that N03 did not predict:**
1. *A chat can be unlocked and still not free to change agent.* A fork made at the start is not `Locked` (`internal/chats/fork.go:276-280`) but its agent is its source's. The check therefore also refuses a fork and a branch. `TestN07AgentChangeRefusedForAForkAndARunAgent` (**[run]**): agent change on a fork at the start → `ErrLocked`; its model can still be changed.
2. *A failed first start leaves an unlocked chat with an error* (`spawnFailed`, `manager.go:897-906`; `Locked` is set only after a successful start, `:1247`). The agent change has to clear that error or the chat stays red under the new agent; 6 lines. `TestN07AgentChangeAfterAFailedStart` (**[run]**): Claude's start fails → status `error`, not locked → change to Cursor → status `ready`, no error → the message starts Cursor once.
3. *A chat on a run has a per-agent rule of its own.* `TestN07AgentChangeOnARun` (**[run]**): no agent named → the run's kind and model; change to Cursor → Cursor's default in the run's group, no session id, the run's folder kept; change back → the run's `sonnet`/`high` again; no defaults recorded.
4. `Create` and `addRunChat` were two copies of the same steps (`manager.go:783-805`, `owned.go:278-307`); the patch routes both through `addRunChat`, which unlike `Create` removes the folder and the token when a step fails.

## S2. Creation with a given id and full configuration

Works. Decisions made and tested: the id must be exactly the form the server generates; a repeat returns the existing chat when every field the request names equals the chat's, started or not; anything that differs answers 409 and changes nothing; every validation happens before anything is made.

**Form of the id.** Today ids come from `uuid()` (`internal/chats/manager.go:2032-2038`: 16 random bytes, version 4, RFC variant, lowercase, dashed) and **nothing validates an id**: routes look it up in a map (`manager.go:547-555`), and the id is used as a folder name (`internal/store/paths.go:29`) and, with a `/`, as a branch path (`internal/chats/owned.go:35-45`). So a given id needs a check. Accepted: `^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$`; anything else is `ErrBadID` → 400. `TestN07CreateWithAnIDWhichForms` (**[run]**): refused are `x`, `chat-1`, `../../etc`, `a/b`, `<uuid>/branches/b1`, upper case, no dashes, version 1, a non-RFC variant, a leading space, a trailing newline; 1,000 ids from `uuid()` all match.

**The call** (patched `manager.go:786-880`): `CreateChat(NewChat{ID, Agent, Group, Board, Run, Cwd, Model, Effort}) (view, made, err)`; `Create` and `CreateOnRun` are now two-line wrappers, so their callers and tests are untouched. With an id the whole call holds a new `createMu`, as `CreateOwned` holds `ownedMu` (`manager.go:71`).

| Second create with the same id | Answer | Test (**[run]**) |
|---|---|---|
| same request, chat not started | 200, the same view, `made=false` | `TestN07CreateWithAnIDIsRepeatable` |
| same request, chat started | 200, the chat as it is now (`locked:true`), no start | same: `Views()` = 1, Cursor `Spawns()` = 1, thread still `user text end` |
| names fewer fields (id and place only) | 200, the existing chat | same |

Why "differs → 409" also for an unstarted chat: create then stays a pure "find it or make it", and a change goes through `PATCH`, which already has the lock rules. The comparison is on the stored values (`sameChat`, patched `manager.go:882-897`), so a repeat that sends the *same* body always matches.

## S4. The sticky agent

Works: one field, `GroupDefaults.Agent` (`json:"agent,omitempty"`), read by `defaults.Agent(d, g)` = the group's → the ungrouped group's → Claude (an unknown kind is skipped), written by `defaults.RecordAgent`.

Recorded (patched `manager.go:1353,1544,1586-1600`): at each *change of agent* in `ConfigureOf`, and at the first message; not at "+"; not for a chat on a run (`c.meta.Run == ""` guards both sites, as before); not for a fork's first message (`c.meta.ForkedFrom == ""`: without this the unlocked fork-at-start case would record its source's agent, and `TestChoiceDoesNotRecordDefaults` would fail). A model or folder change alone does not record the agent; the first message does.

**Run** — `TestN07SecondChatStartsAsTheFirst` (**[run]**): "+" records nothing; change to Cursor, then folder + `composer-2`/`low`; a second "+" in the group **before any message** already starts as Cursor with that folder, model and effort; after the first message the same; a create that *names* Claude gets Claude's own defaults in the group and does not move the sticky agent; chats made in the other group and in the ungrouped group are Claude with the built-in defaults; `Defaults.Groups` has one entry. `TestAgentFallsBackToUngroupedThenClaude` (**[run]**) covers the order. An old file's `last` holds no agent, so after the upgrade every "+" starts as Claude until an agent is chosen (**[inferred]** from `MergeLast` and `Agent`).

## Unknowns that remain

- **A real CLI.** Everything ran against stand-in agents. That a real Claude, Cursor or pi starts cleanly in a chat that was first another kind is shown only as far as "the manager hands it the right options and nothing of the other kind exists in the app's data"; **[not run]** with a CLI. In particular: whether a *failed* real start of the first agent leaves a session file in the CLI's own store.
- **The first message is not repeatable.** Create is; `POST …/messages` is not, and a second one while the turn runs answers 409 (`internal/server/server_test.go:578-579`). A local server that retries "create, then send" after a lost answer to the *send* cannot tell from this prototype whether the message arrived; **[not run]**, outside the brief.
- **A deleted chat's id is free again** (**[inferred]**: delete removes the map entry and the folder; not tested), so a late retry of a create after a delete would make an empty chat.
- **The place in the comparison.** A repeat compares the group too; a chat moved to another group between the two creates answers 409 (**[inferred]** from `sameChat`; not tested). For a chat that only mirrors a remote one the place may not belong in the comparison.
- **Default agent on a run.** I chose the run's kind when the request names none; the brief does not say. One line to change.
- **The web client and the e2e suite** were not touched or run: `web/src/types.ts` still types `defaults.last`, and `web/e2e/app.e2e.mjs:2283,2302` asserts it (N03 S5 rows 8-9).
- **Downgrade.** A new file has no `last`; the old binary then reads an empty `last` and loses nothing else (**[inferred]**); not run.
- Whether the merged values should be written at once: the prototype writes at the next save, so a server that is started and stopped without any change keeps the old file.

## Implications (opinion)

- The plan can keep its main line for both A and B and drop both fallbacks: no "nothing is created at +", no "remote id next to its own".
- State the agent lock as "an unstarted chat *that is not a fork or a branch*"; `Locked` alone is not the condition. The picker in the client needs the same condition (a fork at the start is unlocked but has `forkedFrom`).
- Use the server's own id form (lowercase UUID v4) as the contract for a given id and validate it at the route; today nothing validates ids, and the id becomes a folder name.
- Keep "a differing repeat is 409" and let changes go through `PATCH`; it keeps create free of lock rules. If the local server wants to know whether its create made the chat, add a field or a 201; the prototype returns 200 for both.
- Say in the plan that a group without a value follows the ungrouped group live, and that a seeded group is a copy. Both are true at once and users will see both.
- The migration should be part of the same release that removes `last`, and should write the file at load so the state on disk matches what runs.
- A chat-level idempotency key for the first message is the missing half of "a retry makes no second chat": B makes no second chat, but nothing yet makes no second message.
- Merging `Create` and `CreateOnRun` into one function was a by-product worth keeping: one place resolves agent, folder, model and effort, and the agent change reuses it.
