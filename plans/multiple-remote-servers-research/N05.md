## S4. Certificate generation with what the machines already have

**Answer:** One `openssl req -x509 -config` call does it on LibreSSL 3.3.6; `-addext` also worked there. The result was accepted by `curl --cacert` and rejected by plain `curl`.

Script I ran (`mkcert.sh OUTDIR NAME_OR_IP…`; a name with a non-digit/non-dot character becomes `DNS:`, otherwise `IP:`; this test does not recognise IPv6, **inferred**):
```sh
#!/bin/sh
set -e
out=$1; shift
san=""; for n in "$@"; do
  case $n in *[!0-9.]*) k=DNS;; *) k=IP;; esac
  san="$san${san:+,}$k:$n"; done
mkdir -p "$out"; umask 077
cfg=$(mktemp)
cat >"$cfg" <<CFG
[req]
distinguished_name=dn
x509_extensions=v3
prompt=no
[dn]
CN=$1
[v3]
subjectAltName=$san
basicConstraints=critical,CA:FALSE
keyUsage=critical,digitalSignature,keyEncipherment
extendedKeyUsage=serverAuth
CFG
openssl req -x509 -newkey rsa:2048 -nodes -days 365 -config "$cfg" -keyout "$out/key.pem" -out "$out/cert.pem" 2>/dev/null
rm -f "$cfg"; chmod 600 "$out/key.pem"
openssl x509 -in "$out/cert.pem" -noout -fingerprint -sha256
```
Run: `sh mkcert.sh certs localhost 127.0.0.1 box.example.test 192.0.2.10` → `SHA256 Fingerprint=91:B4:D7:DB:…:78:34:B2`; `ls -l certs` → `-rw-------` for `key.pem` and `cert.pem`. **Verified by run.**

`openssl x509 -noout -text`: `Subject: CN=localhost`, `Not After : Oct 6 07:38:32 2027 GMT`, `X509v3 Subject Alternative Name: DNS:localhost, IP Address:127.0.0.1, DNS:box.example.test, IP Address:192.0.2.10`, `Basic Constraints: critical CA:FALSE`, `sha256WithRSAEncryption`. **Verified by run.**

Serving: this LibreSSL's `openssl s_server -accept 44500 -cert … -key … -www` bound `*:44500` (all interfaces, `lsof`; I killed it at once), and the `-accept 127.0.0.1:44500` form exited immediately. So I used a Go server: `net.Listen("tcp","127.0.0.1:44500")` + `http.ServeTLS(l, nil, cert, key)`, which exits by itself after 20 s; `lsof` showed `127.0.0.1:44500 (LISTEN)`. **Verified by run:**
```
curl -sS --cacert certs/cert.pem https://localhost:44500/   → hello  (rc=0)
curl -sS https://localhost:44500/   → curl: (60) SSL certificate problem: unable to get local issuer certificate  (rc=60)
curl -sS --cacert certs/cert.pem https://127.0.0.1:44500/   → hello
curl -sS --cacert certs/cert.pem --resolve other.test:44500:127.0.0.1 https://other.test:44500/
  → curl: (60) SSL: no alternative certificate subject name matches target host name 'other.test'
```
Listener ended; `lsof` on 44500–44599 empty. Nothing was added to the keychain.

LibreSSL vs OpenSSL 3:
- `openssl req -x509 -addext subjectAltName=DNS:x,IP:10.0.0.1 …` **worked on LibreSSL 3.3.6** (the SAN showed in `-text`; **verified by run**). `-addext` is documented from OpenSSL 1.1.1 (https://docs.openssl.org/1.1.1/man1/req/); older LibreSSL, including older macOS releases, may lack it (**read from documentation, not run**).
- The config-file form (`x509_extensions` section holding `subjectAltName`) is the long-standing one for both (**verified by run** on LibreSSL; OpenSSL 3 **read from documentation, not run**: https://docs.openssl.org/3.0/man1/openssl-req/). The script above uses it, so it is the form I give for both.
- Further OpenSSL 3 points, **read from documentation, not run**: `req -x509` without an `x509_extensions` section gets default extensions (OpenSSL's default config marks it CA), so an explicit `basicConstraints=CA:FALSE` is wise; `-nodes` is deprecated in favour of `-noenc` but still accepted. I did not run `-newkey ec -pkeyopt ec_paramgen_curve:prime256v1` through to the end, so EC keys on LibreSSL are **not verified**; the script uses RSA 2048.
- Validity limits: Apple documents a 398-day maximum for TLS server certificates issued after 1 September 2020 (825 days before), and says it applies to certificates from CAs and not to those from user- or admin-added roots (https://support.apple.com/en-us/103769, **read from documentation from memory of that page; not fetched in this session, not run**). Chromium follows the Baseline Requirements limit for publicly trusted certificates; whether it limits a self-signed leaf the user pins or trusts is **unknown**. 365 days in my script is my choice.
- When a host's IP or name changes the SAN list no longer matches (shown above with `other.test`), so the certificate must be regenerated with the new list; its fingerprint then changes and every client that pinned or trusted the old one must learn the new one. **Inferred** from the failing check.

## S5. The alternative: the Go binary makes the certificate itself

**Answer:** The standard library can do it with no dependency, so a subcommand (e.g. `ai-whiteboard cert …`) would replace the whole `openssl` step of S4 on every platform, and the LibreSSL/OpenSSL differences would no longer matter. A shell script would still be useful around it.

- Standard library (**read from documentation**, https://pkg.go.dev/crypto/x509#CreateCertificate; **not written or run** as a certificate maker): `x509.CreateCertificate` with a template (`DNSNames`, `IPAddresses`, `NotAfter`, `KeyUsage`, `ExtKeyUsageServerAuth`) signed by a self-made `ecdsa` key, written with `encoding/pem`. The fingerprint is `sha256.Sum256(cert.Raw)`. `http.ServeTLS` and `tls.LoadX509KeyPair` take the PEM files, as in my S4 test. `go.mod` stays free of dependencies.
- What the subcommand replaces: the `openssl` call, the SAN string building, the key file mode (`os.WriteFile(…, 0600)`), the fingerprint print, and the need for `openssl` on the machine.
- What a shell script is still useful for (**inferred**): wrapping the subcommand with the machine's names and IPs as defaults; first-time set-up of a server-only folder (right permissions, generate certificate and secret once, print how to start); printing the fingerprint and the secret to copy to the client.
- Finding names and IPs (macOS ones **verified by run**; real values replaced):
  - macOS: `hostname` → `<host>`; `hostname -s`; `scutil --get LocalHostName` → `<host>` (the Bonjour name; use `<host>.local`); `ipconfig getifaddr en0` → `<ip>` (one interface only); `ifconfig | awk '/inet /&&$2!="127.0.0.1"{print $2}'` → two addresses, `<ip>` `<ip>` (more than one interface, so a user has to choose); `route -n get default | grep interface` → the default interface.
  - Linux (**read from documentation, not run**): `hostname`, `hostname -f`, `hostname -I` (all non-loopback addresses, GNU/Linux), `ip -4 -o addr show scope global`, `ip route get 1.1.1.1` (the address on the default route).
- Both families can return several addresses, so no script knows which one a client will use; the user has to choose or pass them.

## Implications (opinion)

- A Go subcommand makes the certificate step identical on macOS and Linux and avoids the LibreSSL/OpenSSL split; the shell script then stays thin. It needs no dependency.
- Names and IPs found automatically give several addresses on one machine; the user should choose or pass them.
- A server-only folder is small (about 23 MB) and suits an archive built by a new script into `bin/`. Putting binaries of every target inside the app adds about 55 MB for little gain when the app already holds the client.
- The server-only start-up should be a script that passes the absolute `-client` path, because the default relative path fails silently.
