# G1 deviations and notes for the integration

Where the plan could not be met as written, or where G1 chose between two readings.

## Files outside G1's list that were touched (compile only)

`cmd/ai-whiteboard/launch.go` and `cmd/ai-whiteboard/remotecmd.go` call `store.ReadServerFile`, `remote.Check`
and `remote.Off`, whose signatures the contract (C1.7) changes, so `go build ./...` failed without a change.
Each change is the smallest that compiles: the new return of `ReadServerFile`, the new arguments of `Check`, and
`remote off` answers exit 2 with a sentence (C2.1's message, shortened) instead of calling `remote.Off`. G2 rewrites
both files. `remoteStatus` still asks the old loopback `/api/remote/status` and so says "older build" until G2.

## Left for G2 in `cmd/ai-whiteboard`

- `serve` binds no control socket and writes `server.json` with an empty `control` (`store.WriteServerFile(p, port, "")`).
  `server.ControlHandler`, `store.ControlSocketPath` and the `Control` field are there for G2.
- `findRunning`, `stop`, `launch`, `relaunch`, `secret` still look for a server at `http://127.0.0.1:<port>/api/hello`
  and so find none (nothing listens there): the commands misbehave until G2, as the plan allows.
- The flags `-port` and `-client` are still parsed (launch.go uses `options.port` and `options.client`); `serve` ignores both.
- `server.ErrBinaryMissing` is kept only because `launch.go` wraps it; nothing in the server uses it any more.
- `cmd/**/*_test.go` do not compile (they name deleted packages); `go test ./...` fails there until G2.

## Choices

- **Events outside the table go to no client.** The bridge had two kinds; an event of a type missing from the table,
  or sent by the wrong sender (a board event through `Broadcast`), went to every page and to no API client. With one
  kind it goes to nobody, and is logged once. `chats`' test helper now marks with a `catalog` event, not an unknown "mark".
- **One kind of client in `editorbridge`.** `New()` takes no argument; `Serve(w, r, id, snapshot)` replaces `ServeSSE` and
  `ServeAPI`; `CloseAll()` replaces `CloseKind`; `Item` has no `Server`; the hand-over delay is the 10 s one for every
  holder (`SetHandoverDelay` sets it). A call about a board nobody holds goes to the holder of the chat's board as a call
  about no board (what an API client got before), and fails at once with `ErrNoClient` when there is none (A16).
- **`ReloadSecret` ends every stream** (all clients are API clients now). Hello needs no secret, so a client that was
  refused after a reload still reads hello.
- **`GET /api/hello` is hello only for exactly that path**: `/api//hello` is redirected by the mux like any other path
  that is not clean (with the secret) and 401 without it.
- **The log lines keep the prefix `remote listener:`** ("logging of refusals as today"); G2's tests may match it.
- **`noRecord`** (DELETE with `?local=1` is 400 `no_record`) is kept: the mock models it, and an API client got it before.
- `GET /api/library` keeps its shape (`libraries`: this server's, `Server` "local", `Name` "This computer", no notice);
  `library.View` lost its `Notice` field, `library.Event` and `library.Removed` are gone; the notice is `libraryNotice`
  of the snapshot (`APISnapshot.LibraryNotice`).
- `ControlHandler`'s `/status` answers `"client": {"listening": false}` for a listener that does not serve (as the old
  `/api/remote/status` did), never null.
- Removed with nothing to replace them: `app.ReorderGroups`, `boards.Service.Reveal`, `chats.ErrServerChosen`,
  `server.Server.Restart/Client/Port/Servers/Remotes`, `remote.Off`, the `PortEqual` check against the server's own port.
- Test names `Level5*` and the files `level5_*_test.go` keep their names; their content is for level 6 and one kind of client.
