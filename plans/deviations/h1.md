# H1 deviations, additions and findings

Nothing in C5.2 is met by less than it says. The following differ from, or add to, what the plan spells out, and a few findings
of the real-process runs are for the owners of the code they are in.

## Additions

1. **`web/dev/host.mjs` takes more than C5.2 lists, and exports more.** `startHost(options)` also takes `dial` (the module's test
   seam for `net.connect`: a script puts a link of its own between the host and a server), `timing` (the module's waits; the
   command line reads `AIWB_APP_WAITS`) and `env` (the environment of the server program it runs), and answers `{ url, port, client,
   face, close() }`. `parseAppWaits` is re-exported from it. Nothing of this is on the command line.
2. **`web/e2e/lib/rig.mjs` (new).** What the four e2e scripts and `web/dev/reallibrary.mjs` share: `Scratch` (a real server with a data
   folder, a port and the stand-in agent; set up with `remote setup`, started with `launch -json`, stopped with `stop`),
   `Scratch.wrapper()` (the program the host runs for this computer's server: the server program with the scratch's flags added to
   `launch` and `relaunch`, and a config file the script writes to stage a server of another build, a failing start, a stand-in
   at another level, a secret), `hostFor`, `hostCall`/`hostApp`, `openPage` (a page with its calls recorded), and `Link` (a TCP relay
   between a host and a server, with the modes of the old `remotechat` link). It is under `web/e2e/**`, which H1 owns.
3. **A fifth script, `web/e2e/localserver.e2e.mjs`.** The plan lists three rewrites, the deletion of `apiclient.e2e.mjs` and the
   adaptation of `app.e2e.mjs`; goal 7.1's real-process cases (a never set-up server shown and then started, a server killed or
   stopped while the page is open and started again by the app, a failing start, another build / too old / the build before, the
   secret replaced while open, the old server list deleted, the app quitting) had no home, so they have one. It builds two
   binaries (versions `e2e-1`, `e2e-2`) and two builds of the page, so it ignores `AIWB_E2E_BIN` and `AIWB_E2E_CLIENT`.
4. **`web/dev/reallibrary.mjs`** (a script of `web/dev` that starts real servers) is rewritten to hosts: A is this computer's server
   of the page's host, B an entry; "another window" and "B's owner" are other apps (hosts with no page), clients of the servers.

## Deviations

5. **`twopages.e2e.mjs`: the two apps are not both with "the same remote servers".** P1 is the app on S's machine (S is its first
   section, started by its host with `--local-bin`), P2 the app on another machine (S is an entry of its list, reached over a link). That
   is the two-machine case the goal draws, and it runs both ways a board can be held (a key without a prefix, a key `<entry>~<id>`).
   P2's "cut off" is the link between its host and S being cut, not its browser going offline. Check (h) ("a page of another
   origin") is now about the host: the page of another origin gets 403 from it, reads nothing, and takes nothing from S.
   The page's client id is the app's (it does not change with a page load): the old check that a reload states a new id is now
   a check that it does not.
6. **`remotechat.e2e.mjs`: "the owner's page" is a second host whose this computer is B.** B serves no page, so its owner is an app on
   B's machine: its sidebar's only section is B. The page's host dials the link in the place of every address but A's, so the
   two extra entries of step 6 (which never connect) get B's certificate behind a closed port's address, as the old link did.
   New checks: this computer's section works all the while B is away; A's server stopped while the page is open is started
   again by the app with the page not loaded again (step 9); the app's list is a 0600 file in its state folder and A's data folder
   holds no list. The stand-ins of step 9 are HTTP/2 servers (a client of the API speaks h2 only) and answer hello without the
   secret (A10): "Secret not accepted" is a refusal at the stream, not at hello. A "closing" of the owner's app precedes B's stop
   (its host would start B again). "Restart A to forget a changed certificate" is a restart of the page's host (a state of a connection
   is not kept across the app).
7. **`app.e2e.mjs` is adapted, not run** (it is paid). What changed: the server is a `Scratch` with the real agents, set up once and
   started with `launch -json`; the pages are the host's; a restart of the server (steps 1, 7, 11, 20, 25, 26) closes the host first
   (the app would start the server again with the old environment) and opens it again on the same port; the script's own reads
   (`get`) go through a *probe*, another app with no page that stays subscribed to the server, so that they do not depend on a page
   being open; step 10's "a client with no window" is the probe; the page's requests are matched as calls to the host
   (`isCall`, `callIn`); the second page of step 9f is a second app whose server list holds this server; steps 9a to 9e (two pages
   on one board: take, hold-up, cut, drafts, another origin) are reported skipped, run without agents by `twopages.e2e.mjs`;
   `.side-addgroup` and `.offline` are gone from the page and are replaced (the head's "+" menu, this computer's section saying
   "Connected"). Only `node --check` was run. The selectors of the other steps are those of the page before W2 and nothing but
   `.side-addgroup` and `.offline` was looked for; a person who runs it may find more.

## Findings in code H1 does not own

8. **`desktop/conn/conn.js` `enter()` keeps a stale reason (J1).** `if (s.state === e.state && this.cause === e.cause && retries(e.state)) return;`
   skips the update when this computer's entry is `not_started` again, so a start that fails for another reason than the one before
   shows the first reason. Seen with `localserver.e2e.mjs`: the server is stopped and the start fails with "A" (the section shows
   "A"); Retry, now failing with "B" (or with output that is no JSON line): the section still says "A" and `server_state` is not
   emitted. A user's way to it: never set up (the message names `remote setup`), the set-up is run but the start then fails for
   another reason (a busy MCP port): the section still names the set-up. The script avoids it (it goes through "Connected" between
   two failures) and does not check it.
9. **An empty folder `aiwb-<16 hex>` is left in the temporary folder for every data folder whose path is longer than 100 bytes**
   (G2: the fallback path of the control socket). The socket and `server.json` are removed at a stop, the folder is not.
   The machine's temporary folder held 4,180 of them after the waves' tests and these runs.

## For the integration workstream

- `AGENTS.md` and the docs should say how the e2e scripts are run now: `cd web && npm run build` first (they serve `web/dist`),
  `npm install --no-save playwright` and `npx playwright install chromium`, then `node web/e2e/<name>.e2e.mjs`; the four free
  scripts take about 7 s (newchat), 45 s (twopages), 60 s (remotechat) and 20 s (localserver) alone; `localserver` and
  `reallibrary` build the binary and, for the first, the page.
- `desktop/test/faces.test.js` runs the real `preload.js`, the real IPC face and the real `hostface.mjs`, and takes the scheme's
  handler `pictureResponse` out of `desktop/main.js` by its source (it needs Electron's session otherwise). If that function is
  renamed or moved, that test fails with a message saying so; moving it to `lib.js` would let the test import it.
- The IPC face and the HTTP face differ in three ways the test pins down and the goal's "every way means the same" may want a
  line on: (a) `owner.openLog` and `owner.reveal` are done by the app and answer 501 `not_here` at the host; (b) an address
  of the picture scheme that is malformed (a bad entry id) is a 400 at the scheme, and at the host the module's 404 `no_server`;
  (c) a cancelled call answers `499 cancelled` over IPC and the browser's own abort over HTTP (both reject in the page).
- `web/package.json`'s `test` script (W2's) lists `dev/hostface.test.mjs`; `dev/host.test.mjs` is run with `node --test web/dev/host.test.mjs`
  and is not in it (H1 does not own the file). Add it there if it is to run with `npm test`.
