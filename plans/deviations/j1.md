# J1 deviations and additions

Nothing in a contract of section 3 of the plan is met by less than it says. The following differ from, or
add to, what C3 spells out.

1. **More files than C3.1 lists**, all in `desktop/conn/`: `sse.js` (the event stream's reader), `text.js`
   (the clean/hide helpers of `test.go`), `manager.js` (the port of `manager.go`: the list, one connection per
   entry, the operations; `index.js` is only `createClient`).
2. **Two test seams on `createClient`** that C3.2 does not list: `dial` (replaces `net.connect`) and `roots`
   (PEM roots a certificate without the self-signed box is verified against). Without them the module is as
   C3.2.
3. **One more timing field**, `status` (10 s): the time of `status -json` for `owner.status`. C3.11 gives it
   none. Not reachable from `AIWB_APP_WAITS`.
4. **Events before the snapshot are delivered.** The Go relay passed over what came before the snapshot; C3.4
   step 1 says the hello and the snapshot reach the page "as the server sent them", so the events before the
   snapshot (the hello; at most 64 are held) are emitted in order, just before the snapshot.
5. **Certificate errors**: the handshake runs with `rejectUnauthorized: false` and the module judges the
   certificate itself (pin, or `authorizationError` of Node), so that nothing is written to a refused one and
   the order of Go's table holds (name, then expiry, then self-signed, which Node's own error order does not
   give). The state `certificate_not_accepted` shows the outcome's sentence as its detail; the `detail` of a
   Test connection result is Node's error code.
6. **ALPN offers `h2` and `http/1.1`**, and an answer of `http/1.1` is `not_aiwb` (C3.5 "ALPN not `h2`").
   Offering `h2` alone would give a TLS alert (`tls_error`) instead.
7. **A remote entry that is this computer's server**: when this computer's instance id becomes known (from
   `launch -json`, or the local hello) and a connected remote entry has the same id, that entry's stream is
   ended so that its next attempt finds `is_local`. Nothing in C3 says this; without it a remote entry that
   connected first would stay a second section of this computer.
8. **Body limits by route, not by kind of body** (C3.7 step 3): `{json}` and `{bytes}` are both cut at 2 MiB,
   at 128 MiB for the scene and at 5 MiB for an image upload.
9. **`owner.retry` is a Retry in every waiting state** of this computer's loop, including
   `secret_not_accepted` and `certificate_changed` (where the remote entries' Retry waits for an accept);
   the state `not_started` retries with the back-off like `unreachable`.
10. **HTTP/2 windows are 4 MiB per stream, 8 MiB for the connection** (Node's default is 64 KiB), so that a
    drawing or a picture over a VPN does not move one window per round trip. `maxSessionMemory` is 256 MB.
11. **Not tested**: an answer above 160 MiB (`bad_answer` for a call). The same `maxBytes` mechanism of
    `Session.fetch` is tested through hello (64 KiB) and pictures (5 MiB); a 160 MiB test would cost seconds
    and hundreds of MB of memory.
