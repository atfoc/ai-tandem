# D1 deviations and additions

No contract of section 3 of the plan is met by less than it says. The following differ from, or add to, what C4 and the D1
section spell out.

1. **`pagePath` and `linkAction` take a page URL, `setAppURL` is `setPageURL`.** C4.5 says `linkAction` is kept "with the page URL
   in place of an origin"; `attachLinkHandlers` returns `setPageURL` (was `setAppURL`). A navigation stays only to the page's own
   URL with another hash; a query is another page and is dropped.
2. **`attachCloseFlush` lost its `onQuitCancelled` option** (it only served the reconnector, which is gone), with its tests and
   the tests of `resumeAfterCancelledQuit`.
3. **`lib.js` also exports** `pagePath`, `withoutHash`, `atPage`, `PICTURE_SCHEME`; `serverLogPath(home)` now takes the data
   folder (the `home` the launch printed) and returns `<home>/server.log`.
4. **`parsePictureURL` also checks the chat and image ids** (the shapes of C3.8) and refuses a query, user info and an empty
   segment, so that a bad address is a 400 before the module is asked; the module still answers `image_id` for the same ids.
5. **`aiwb:app` answers an operation outside C3.10's list** with `{status: 404, text: {code: "no_op"}}` (what the module
   answers an unknown operation), not a rejected promise; a refused sender or a malformed payload does reject.
6. **A call cancelled by `aiwb:cancel` answers `{status: 499, code: "cancelled"}`** instead of rejecting the invoke (a rejection
   is logged by Electron as a handler error; the page has already dropped the call).
7. **`aiwb:call` refuses a second call with an id still in use** (rejects) and an `id` longer than 200 characters.
8. **The IPC face has two more methods**, `watchWindow(win)` (ends the subscription on a main-frame cross-document navigation,
   `render-process-gone` and `closed`) and `close()` (sends `"closed"` to the page and ends the subscription, at quit); both
   are what C4.2 describes, written as methods because the window is made after the face.
9. **The window shows on `ready-to-show`** (created hidden), not after the load of a server URL. A main-frame load failure of
   the page (not code -3) shows an error box: the one dialog left, for a broken install, never for a server.
10. **`will-quit`, not `before-quit`, closes the client**, because the unsaved-changes dialog can still cancel a quit after
    `before-quit`.
11. **`desktop/e2e/app.e2e.mjs`** observes the page through the preload surface (`window.aiwbApp.onEvents`) and does not read
    the page's own screens: the page in this branch is W1's interim one, and W2 changes its sections. Playwright's
    `_electron` drives Electron 44.4.5 on macOS (a real window is opened for a few seconds; there is no headless Electron
    there). `AIWB_E2E_APP` runs a built `AI Whiteboard.app` instead of the checkout; it passed against a build of this branch
    (`scripts/build-app.sh`), whose `app.asar` holds `conn/**` and `ipcface.js` and nothing of `web/dev`.
12. **Not tested by a test**: the page-level checks "window never leaves the app's page" beyond `linkAction` and
    `attachLinkHandlers` with fakes; that bringing the window forward on a second start focuses it (the e2e checks the second
    start ends and leaves one window); `owner.openLog` and `owner.reveal` against the real `shell` (fakes in
    `ipcface.test.js`, so that the e2e never opens the user's editor or Finder).
