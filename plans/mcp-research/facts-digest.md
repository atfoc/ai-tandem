## 2. Why Cursor used a command endpoint (not an ACP limitation)

- Deleted research docs (recoverable via `git show bf2f34a^:docs/...`) record: every MCP server attempt (ACP `session/new.mcpServers`, `.cursor/mcp.json`, `agent mcp enable`) was refused with "blocked by team policy"; ACP advertises `mcpCapabilities:{http:true,sse:true}`; accepted decision "Cursor's board tools go through commands, not MCP" (`docs/features/app.md:259-260,417-421`).
- Installed CLI (2026.09.28-64d2043) supports streamable HTTP MCP via `~/.cursor/mcp.json`/`.cursor/mcp.json` and ACP `mcpServers` union `{name,url,headers}+type:"http"|"sse"` / stdio (bundle `8096.index.js`, mapping `3115.index.js`). `url` is used verbatim and query strings are preserved by URL normalization; org allow-listing is enforced by `allowedMcpConfiguration` (`allowedMcpServers[].server_url` patterns / network allowlist).
- **Live experiment supersedes pattern-based inference**: current org policy matches the URL exactly. Only `http://localhost:6006/mcp` connects; `?token=`, path tokens, trailing slash, `127.0.0.1`, `[::1]` all fail with exactly `"Blocked by team policy"` (silent at ACP level; only in `$TMPDIR/cursor-agent-logs-<uid>/latest.log`). Headers on the exact URL are forwarded and accepted (`headers:[{name,value}]`, at least `Authorization` and custom `X-Board-Token` observed server-side). ACP schema requires the `headers` array even when empty. `--approve-mcps` does not override team policy.
- Claude Code 2.1.284 supports HTTP MCP with custom headers (`claude mcp add --transport http --header ...`; top-level `--mcp-config` JSON strings/files). Exact header JSON shape inside `--mcp-config` was not live-tested.
- `localhost` reaches a 127.0.0.1-only or ::1-only listener from Node 24/26, Python, curl; both bound → `::1` preferred.

## 4. Feasibility constraints for the unified endpoint (from code)

- A fixed `/mcp` path has no chat identity today: `ServeMCP` reads only the path token; `ByToken("")` fails; there is no server-side "current chat" and no MCP session state. Identity must be carried in a header/query interpreted by the server.
- Token is the only auth on `/mcp` and `/agent`; guard's Host check is the only network constraint (DNS-rebinding mitigation), and it is parameterized by the single `Server.Port`.
- Options considered for 6006: (a) second listener in the same process (shared `Bridge`/`Chats` singletons; guard must accept the new host:port; `server.json`/launch/stop/Electron stay on 4747), (b) move whole app to 6006 (changes app URL; race with stale `server.json`), (c) external reverse proxy (guard would 403 unless Host rewritten; extra process not managed by launch/stop). Constraints only.
- Tests/e2e/desktop fixtures that hardcode ports or the command endpoint: see §1 list; `web/e2e/app.e2e.mjs:497-515` exercises the real Cursor command-endpoint edit and would fail when it is removed unless Cursor is migrated to MCP.
